# Phase 12: Product UX And Admin

## Goal

Make the app feel like a team coordination product instead of an internal database viewer.

## Tasks

- [ ] Add first-class team dashboard.
- [ ] Add person detail page with owned tasks, commitments, follow-ups, and recent updates.
- [ ] Add task memory page with timeline, citations, snapshots, and proposals.
- [ ] Add admin settings for stale Jira threshold and follow-up tone.
- [ ] Add onboarding checklist for connecting Slack and Jira.
- [ ] Add privacy copy that explains coordination use and avoids monitoring language.
- [ ] Add empty states for teams with no data.
- [ ] Add search box for person/task/ticket lookup.

## Acceptance Criteria

- A manager can find status by person, task, or Jira key from the UI.
- A user can see what memory exists about a task and where it came from.
- Admins can tune stale-ticket thresholds without code changes.
- The UI language frames the system as coordination memory, not employee surveillance.
